# Требования и структура Frontend-части (My Cloud)

## 1. Стек технологий
- **Библиотека:** React (18.0+)
- **Маршрутизация:** React Router (v6)
- **Управление состоянием (State Management):** Redux Toolkit (RTK)
- **Язык:** TypeScript (очень рекомендуется) или JavaScript
- **Сборщик:** Vite (рекомендуется, работает быстрее Create React App)
- **Работа с API:** Axios или встроенный `fetch` / RTK Query

## 2. Структура страниц (Роутинг)

1. **Главная страница (`/`)**
   - Общая информация о приложении.
   - Ссылки на вход и регистрацию.
2. **Страница регистрации (`/register`)**
   - Форма регистрации (логин, полное имя, email, пароль).
   - Валидация полей (только латиница, проверка пароля и т.д.).
3. **Страница входа (`/login`)**
   - Форма аутентификации (логин, пароль).
4. **Хранилище пользователя (`/storage`)** - *Доступно только авторизованным.*
   - Список файлов.
   - Загрузка новых файлов (с комментарием).
   - Действия с файлом: скачать, переименовать, изменить комментарий, удалить, получить публичную ссылку.
5. **Панель администратора (`/admin`)** - *Доступно только администраторам.*
   - Список пользователей (логин, имя, email, кол-во и размер файлов).
   - Управление пользователями: удаление, изменение статуса администратора.
   - Ссылка на просмотр хранилища пользователя.
6. **Публичная страница скачивания (`/public/:token`)** - *Доступна всем.*
   - Скачивание файла по специальной ссылке.

## 3. Компоненты (UI)

- **Layout** (Общая обертка): Содержит шапку (Header) и основную часть страницы.
- **Header**: Навигационное меню (Вход, Регистрация, Выход, Ссылка на админку для админов).
- **FileCard / FileListItem**: Карточка файла в хранилище.
- **UserCard / UserListItem**: Карточка пользователя в админке.
- **Modals / Dialogs**: Всплывающие окна (например, для подтверждения удаления или переименования).

## 4. Пошаговый план разработки (Roadmap)

### Шаг 1. Инициализация проекта и базовая верстка
- Создание пустого React-приложения через Vite.
- Настройка React Router: создание базовых компонентов-страниц и переходов между ними.
- Настройка базового Layout (шапка с динамическим меню в зависимости от статуса авторизации).

### Шаг 2. Настройка State Management (Redux) и интеграция с API
- Настройка `store` с помощью Redux Toolkit.
- Создание `authSlice` (состояние пользователя: данные, залогинен ли он, админ или нет).
- Настройка API-клиента (например, Axios) для работы с backend (учитывая `session auth` и `CSRF`).

### Шаг 3. Реализация авторизации и регистрации
- Верстка форм регистрации и входа.
- Клиентская валидация (проверка логина, email, пароля на соответствие требованиям).
- Подключение API-запросов (`/api/users/register/`, `/api/users/login/`, `/api/users/logout/`).
- Защита маршрутов (PrivateRoute) — редирект неавторизованных пользователей на страницу входа.

### Шаг 4. Интерфейс хранилища (Storage)
- Получение списка файлов (`/api/files/`) и вывод на экран.
- Верстка формы загрузки файла с комментарием.
- Реализация скачивания файлов (`/api/files/<id>/download/`).
- Реализация действий с файлом: удаление, переименование, обновление комментария, получение публичной ссылки.

### Шаг 5. Панель администратора
- Защита маршрута `/admin` (только для `is_staff=true`).
- Получение списка пользователей с бекенда.
- Функционал изменения статуса администратора и удаления пользователей.
- Просмотр файлов выбранного пользователя.

### Шаг 6. Публичные ссылки
- Страница скачивания файла без авторизации по токену.
- Обработка запроса скачивания `GET /api/public/files/<token>/`.

### Шаг 7. Финализация и полировка
- Добавление уведомлений (Toasts) об успешных или неуспешных действиях.
- Добавление индикаторов загрузки (Loaders/Spinners) во время ожидания ответа от сервера.
- Обработка ошибки 404 (страница не найдена).
